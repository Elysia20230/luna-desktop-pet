# 修改指南

这份文档假设你**只会改文本、不会写程序**。每条都写了「改哪个文件」和「改成什么样」。

改完记得**重启程序**（托盘 → 退出 → 重新双击 `启动露娜.bat`）。

---

## 1. 想让她说话更像露娜

人设来自工作区里的文件（不需要动代码）：

```
..\background\露娜_系统提示词_蒸馏组装版.md
```

程序只取其中 **Part A**（主提示词）和 **B1**（关系图谱）。想让某句话永远生效，
更简单的办法是：**设置 → 其它 → 补充设定**（写进 `config.json` 的 `persona.extra_note`），
比如填：

> 最近主人在赶论文，说话可以稍微温柔一点。

---

## 2. 想让她说话更短 / 更长

设置 → 对话 → **单次回复字数上限**（默认 60 字）。

⚠️ 这个值太小（< 20）会把话截得很生硬；太大（> 150）就不像说话，像念作文了。

## 3. 想改"什么情绪配什么表情"

文件：`assets/expressions.json`。它长这样：

```jsonc
{
  "emotions": ["平静", "微笑", ...],          // 12 档情绪名，程序认这些词
  "index_labels": { "7": "害羞（脸红）" },     // 每个编号长什么样，只是给人看的注释
  "candidates": {
    "害羞": [7, 17, 12, 18],                  // 按优先级排；某套衣服没有 7 就用 17
    "生气": [18, 8, 17]
  },
  "closed_indices": [1, 4, 6, 11, 14, 16],    // 哪些编号适合用来"眨眼"
  "groups": {}                                 // 想给某套衣服单独配，就写在这里
}
```

- 程序会按 `candidates` 的顺序，找**当前这套衣服真的有**的第一个编号。全都没有时，取编号最接近的那个，所以不会出现空白。
- 想给某一套衣服单独指定，就在 `groups` 里加，例如：

```jsonc
"groups": {
  "5_0": { "害羞": [12], "生气": [13] }
}
```

- 编号含义见 `index_labels`（0~19 大致是：0 平静、1 闭眼、4 闭眼笑、5 惊讶、7 害羞、9 笑、13 意外、16 低头、18 赌气……）。
  想亲自确认，运行 `tools/make_sheets.py` 生成对照图后打开看。

### 3.1 顺带说一句：动作（抱臂 / 抬手）

文件名 `lun_<尺寸>_<造型a>_<动作b>_<编号>.png` 里，**a 是穿什么，b 是怎么站**：

| b | 动作 | 有哪些造型 |
|---|---|---|
| `0` | 抬手（手放胸前，默认） | 造型①~⑦都有 |
| `2` | 抱臂 | 造型①~⑥有，造型⑦没有 |

"按情绪换动作但不换衣服"就是**只改 b**。配置在 `assets/expressions.json` 的这三段：

```jsonc
"pose_labels": { "0": "抬手", "2": "抱臂" },     // 动作名字（右键菜单里显示）
"default_pose": "0",                              // 默认站姿
"emotion_pose": { "得意": "2", "生气": "2" },     // 说到哪种情绪就换成哪个动作
"pose_candidates": {                              // b=2 专用的表情表
  "2": { "平静": [1, 2, 5], "害羞": [12, 18, 17] }
},
"closed_indices_by_pose": { "2": [0, 10] }        // 抱臂那套里哪几个编号适合眨眼
```

- **抱臂组的编号语义和抬手组不一样**（同一编号长得不同），所以 `pose_candidates` 单独一张表；
  解析顺序是：`groups` 覆盖 → `pose_candidates`（仅 b≠0）→ `candidates` → 最近编号。
- 某套造型没有抱臂（比如造型⑦）或某个尺寸族缺这套图时，程序自动退回能用的组合，不会黑屏。
- 想关掉"自动换动作"：设置 → 立绘 →「说话时按情绪顺手换个动作」（`sprite.auto_pose`），
  或者右键菜单 →「换动作」→「自动」取消勾选。

## 3.2 想改「什么时候穿什么衣服」

规则全在 `assets/wardrobe.json`（没有就用内置默认表，改这个文件不用动代码）：

```jsonc
{
  "outfits": {
    "0": { "name": "学院装·夏", "seasons": ["spring", "summer"], "random": true },
    "2": { "name": "学院装·秋冬", "seasons": ["autumn", "winter"], "random": true },
    "5": { "name": "家居服",     "occasion": "sleep", "random": false }
  }
}
```

字段说明：

| 字段 | 作用 |
|---|---|
| `name` | 右键菜单和设置里显示的名字 |
| `seasons` | 哪几个季节会随机轮到它：`spring/summer/autumn/winter` |
| `random` | `false` 表示只会在「指定场合」穿（比如睡衣），不会被随机抽到 |
| `occasion` | `sleep` = 夜间专用；换成别的字符串就不参与夜间切换 |

判定顺序（`app/wardrobe.py` 的 `desired()`）：**夜间区间 → 若 `occasion=sleep` 那套可用就用它**；
否则按当前季节从 `seasons` 命中的几套里挑（`random:false` 的排除在外）。

常用调法，都在 设置 → 立绘：

| 想做的事 | 设置项 | 配置键 |
|---|---|---|
| 深夜穿哪套 | 「夜里换这套」 | `behavior.outfit_night_outfit`（填造型编号，`5` = 家居服） |
| 几点到几点算深夜 | 「深夜从/到」 | `behavior.outfit_night_from` / `outfit_night_to`（默认 22→6，跨零点也行；起止相同 = 关闭） |
| 最短多久换一次 | 「最短间隔」 | `behavior.outfit_min_gap_min`（默认 30 分钟，0 = 不限） |
| 手动选的衣服保多久 | — | `behavior.outfit_manual_hold_min`（默认 120 分钟） |
| 同季节内随机 | 「同季随机」 | `behavior.outfit_random_in_season` |
| 强制当某个季节 | 「季节」下拉 | `behavior.outfit_season`（留空 = 按真实日期） |
| 整个关掉 | 「按时间自动换装」 | `behavior.outfit_auto`（右键菜单里也有这个开关） |

要加新衣服：把立绘按 `lun_<族>_<a>_<b>_<编号>.png` 放进 `Sprite/`，再在 `wardrobe.json` 的
`outfits` 里加一条 `"7": {...}` 就能被认出来（`app/sprites.py` 会扫到新组）。



新建 `assets/outfits.json`：

```jsonc
{ "0_0": "校服", "0_2": "校服·便装", "5_0": "睡衣" }
```

右键菜单里就会显示这些名字。没写的保持"造型⑨"这种默认叫法。

如果想让她一启动就大一点/小一点，改 `app/ui/pet_window.py` 里 `fit_to_screen()` 的
`ratio`（默认 `0.42`，表示立绘高度占可用屏幕高度的 42%；改 0.55 更大、0.30 更小）。
这个自动尺寸只在**第一次启动**（还没有记住位置时）生效，之后你滚轮调过的大小会被记住。

## 5. 想换配色 / 字体

- 对话窗颜色：`app/ui/chat_window.py` 顶部几个常量
  `C_PANEL`（面板底色）、`C_USER`（你的气泡）、`C_LUNA`（她的气泡）、`C_TEXT`、`C_HINT`。
- 设置/记忆面板配色：`app/ui/panels.py` 里的 `_DIALOG_QSS` 字符串（就是一段 CSS）。
- 字体：搜 `Microsoft YaHei UI` 替换成你装的字体名（例如 `LXGW WenKai`）。

⚠️ 面板里凡是**套了 `QScrollArea` 的页**（目前只有「语音」页），必须同时有这三条，
否则滚动内容会用系统调色板刷出一块浅灰底，和别的页签对不上：

```css
QScrollArea{background:transparent;border:none;}
QScrollArea > QWidget > QWidget{background:transparent;}   /* viewport 里的内容 */
QWidget#voicePage{background:transparent;}
```

另外别给滚动区的内层 `QWidget` 单独写 `QLabel{color:...}`：子控件的样式表优先级更高，
会把这一页的标签色、`hint` 色从全局样式上顶掉（这个坑已经踩过一次，`tests/test_dialog_style.py` 会盯着它）。

## 7. 想改记忆的"聪明程度"

`config.json` → `memory`：

| 键 | 含义 | 调大会怎样 |
|---|---|---|
| `top_k` | 每次对话注入几条记忆 | 更"记得"你，但更费 token |
| `auto_extract_every` | 每几轮提炼一次新记忆 | 更少提炼、更省钱；设 0 = 关闭 |
| `max_facts` | 最多存多少条 | 超出后老的会被压成摘要 |
| `embedding.query_timeout` | 对话时"给这一句提问算向量"最多等几秒（默认 8） | 网络差就调大；调小则更容易退回关键词检索 |

**为什么"记忆变多"也不会卡界面**：检索、拼人设这两步已经放进后台线程
（`app/chat/engine.py` 的 `make_system()`），界面线程只做一次很便宜的拷贝。
`query_timeout` 那一层是第二重保险：向量接口偶尔抽风时，最多等这么久，
之后 60 秒内不再尝试，这段时间只用关键词（BM25）检索，聊天照常。

**三个超时键分别管什么**（`config.json` → `api` / `memory`）：

| 键 | 默认 | 管什么 |
|---|---|---|
| `api.timeout_connect` | 20 秒 | 连不上 DeepSeek 时，多久算失败 |
| `api.timeout_total` | 120 秒 | 一次流式回复最多等多久（含生成中） |
| `memory.embedding.query_timeout` | 8 秒 | 算"这句话的向量"最多等多久 |

打分公式在 `app/memory/retriever.py` 的 `retrieve()` 里：
`0.65*向量 + 0.20*关键词 + 0.15*(权重×新近度)`。
想更看重字面命中就把 0.20 调大；想更懂"意思"就把 0.65 调大（两个一起调也行，只影响排序）。

## 8. 想换「我是谁」／加自己的角色卡

她面前的人不同，脾气和称呼就不同。这份设定放在 `assets/roles.json`：

```jsonc
{
  "roles": [
    {
      "id": "asahi",                  // 程序内部用的编号，别和别的重复
      "label": "小仓朝日",             // 设置界面里显示的名字
      "user_avatar": "",              // 头像路径，可以留空（暂时没用到）
      "rules": "你面前的人是**小仓朝日**……你叫他「朝日」，他叫你「露娜大人」。"  // 一整段规则
    }
  ]
}
```

改法有两种：

1. **只想换个称呼**：把 `label` 改掉（比如改成你自己的名字），规则里的称呼一起改；
2. **想多一个人**：复制一整块 `{...}`，改 `id` 和 `label`，重启后在
   **设置 → 对话 →「我是谁」** 里就能选到。

优先级：`设置 → 对话` 里指定的文件 > `assets/roles.json` > `~/Luna-Chat/shared/roles.json` > 内置的朝日/游星。
文件写坏了不会崩：会退回内置角色，并在启动时用托盘消息提示一句。

## 9. 想改主动搭话的节奏 / 气泡长相

**多久说一句**：设置 → 其它 →「每隔多久主动说一句」（`behavior.idle_lines_min`，0 = 永远不主动）。
**说完后多久不烦你**：同页「你说话后多久内不打扰」（`behavior.idle_min_gap_min`，默认 3 分钟）。
**气泡停多久**：同页「桌面气泡停留多久」（`behavior.bubble_seconds`，默认 9 秒）。
**开口前先看一眼屏幕**：设置 → 看屏幕 →「她主动开口前，先偷看一眼屏幕」
（`behavior.idle_use_screen`）。⚠️ 只读窗口标题，不截图上传——除非你还开了视觉模型。

想改气泡的长相（宽度、圆角、配色、字体大小），打开 `app/ui/bubble.py`，最上面的
几个常量就是全部可调项：

```python
TEXT_MAX_W = 340        # 文字最宽多少像素，超了就换行
PAD_X = 14              # 左右内边距
TAIL_H = 10             # 下面小尖角的高度
BG = QColor(38, 31, 56, 236)         # 底色
```

气泡平时贴在她头顶；如果她已经贴着屏幕底、输入框翻到了头顶，气泡会改贴**输入框**的头顶
（见 `main.py` 的 `_bubble_anchor()`），免得两块叠在一起。

**输入框（脚下那条）的位置规则**在 `app/ui/input_bar.py` 的 `follow()` 里：

```python
BAR_W, BAR_H = 460, 54   # 宽度、高度
GAP = 8                  # 和她的间距
BAR_H + 24               # 脚下至少留这么高才往回贴，24 是"迟滞"，防止来回跳
```

想改她"自己会说哪些话"（没填 Key 时的兜底台词，含主动搭话那几句），在
`app/chat/offline.py` 的 `OFFLINE_LINES` / `PROACTIVE_LINES` 里加句子即可，
`{name}` 会被替换成角色卡里的称呼。

**想立刻试一次主动搭话**：设置 → 其它 →「让她现在说一句」，不用等计时器。

## 9.0 想改「看看我在干什么」的表现

这条链路和普通对话**刻意分开**：点一次 = 现拍一张 + 她随口点评一句，
不写 `data/history.json`、不进「聊天记录」、不触发记忆提炼。

要改的地方只有三处：

| 想改什么 | 改哪里 |
|---|---|
| 触发她说话的那句"假用户消息" | `app/chat/engine.py` 的 `SCREEN_TRIGGER` |
| 她这一刻的说话场合（字数、别复述细节） | `app/persona.py` 的 `system_prompt(..., screen_comment=True)` 那一段 |
| 没填 Key / 接口失败时的兜底台词 | `app/chat/offline.py` 的 `SCREEN_LINES`（`reply_screen()` 随机取） |

流程本身在 `app/chat/engine.py` 的 `send_screen_comment()`：
它只接 `screen_said` 信号，**不要**把它改成 `send()`——一旦改了，偷看就会变成一轮真对话，
记录和记忆里都会多出一条「看看我在干什么？」。界面那一端在 `main.py` 的
`_on_screen_said()`（故意没有 `chat.add_message()`）。

隐私边界在 `app/screen/context.py` 的 `build_digest()`：标题命中 `SENSITIVE_HINTS`
就在**截图之前**返回，所以命中隐私词时连画面字节都不会产生。
`tests/test_screen_privacy.py` 专门守着这条顺序（命中时截图函数一旦被调用就报错）。

## 9.1 想改"说完话多久恢复默认姿势"

- 设置 → 其它 →「表情/动作保持多久后恢复」（`behavior.emotion_hold_seconds`，默认 8 秒，0 = 一直保持）。
- 同页「说完一句后自动恢复默认姿势与表情」（`behavior.restore_after_reply`，默认开）。
- 想马上恢复：右键菜单 →「换动作」→「恢复默认姿势」，或者关掉对话窗（关窗也会恢复）。

流程是：模型回一句带情绪的话 → 按 `emotion_pose` 换动作 + 按 `candidates` 换表情 →
保持 N 秒 → 自动回到 `default_pose` + "平静"。期间如果你又发了一句，计时器会重新开始。

## 9.2 想改语音（日语朗读）

**开关与基本参数**：设置 → 语音。对应的配置键都在 `config/config.json` 的 `voice` 段：

| 键 | 作用 |
|---|---|
| `enabled` | 总开关。关掉就完全不出声，也不启动服务 |
| `autostart` | 程序启动就把 GPT-SoVITS 服务拉起来（等于提前预热，第一次说话会快些） |
| `root` / `python` | GPT-SoVITS 目录；`python` 留空 = 用 `<root>/runtime/python.exe` |
| `gpt_weights` / `sovits_weights` | 两个权重，路径相对 `root` |
| `voice_map_file` | 音色表；留空 = `assets/voice_emotions.json` |
| `port` | 本地服务端口，默认 9888 |
| `max_chars` / `first_chars` / `segment_chars` | 整句字数上限 / 第一段多长 / 后面每段多长 |
| `speed` | 语速（在音色表里按情绪单独设，见下） |
| `volume` | 音量 0~1 |
| `speak_proactive` | 她主动搭话时也念出来吗 |
| `translate_model` | 中→日翻译用哪个模型（留空 = 跟对话用同一个） |
| `start_timeout` / `probe_timeout` / `timeout_seconds` | 等服务就绪的上限 / 探活超时 / 单次合成超时 |

**情绪 → 音色**：`assets/voice_emotions.json`。`refs` 是"音色名 → 参考音频 + 那句音频的日语原文"，
`emotion_map` 是"情绪 → 音色名"。加一套音色只要：

1. 把 wav 放进 `refs.dir` 指向的模型目录；
2. 在 `refs` 里加一条 `{"label": "冷淡", "file": "xxx.wav", "prompt": "那段音频的日文原话"}`；
3. 在 `emotion_map` 里让某些情绪指向它。

改完重启即可（设置面板的 12 行下拉也会自动列出新音色，保存时直接写回这份 json）。

**为什么"分段"**：整句合成要 8~10 秒（纯 CPU）。所以她的回复一到就开始**按标点切段**，
第一段合成完就出声，后面的边合成边排队播——体感从"等十秒"变成"几秒内开口，然后连着说"。
想调这个节奏，就改上面的 `first_chars`（越小越快开口）和 `segment_chars`。

**没声音怎么查**：`logs/tts_server.log` 是服务端日志（能看到权重有没有挂上）；
`logs/运行错误.txt` 是程序自己的异常；`data/voice/` 里能直接双击试听合成的 wav——
放得出声说明合成没问题，问题在播放（`app/voice/player.py` 用的是 `winsound`，只认 WAV）。

## 9.3 想换「心情大好～」那句彩蛋

设置 → 其它 → 「让她说一句「心情大好～」」：放一段**本地**日语录音（`大変に気分がいい～`），
同时换成得意 + 抱臂，气泡显示中文。它不经过翻译、不经过语音服务、不写聊天记录，
所以语音开关关着也能用。

**换成自己的录音（推荐，不用改代码）**

1. 准备一个 **16-bit PCM 单声道** 的 wav（任意采样率；不是这种格式 `winsound` 播不出来）；
2. 覆盖 `assets/voice/taihen_ni_kibun_ga_ii.wav`；
3. 重启程序即可。

手里只有 `xxx.ogg` / `.mp3` 也没关系——项目里有转码脚本：

```bat
.venv\Scripts\python.exe tools\make_signature_audio.py
```

它默认读 `assets/voice/taihen_ni_kibun_ga_ii.ogg` 写成同名 `.wav`（脚本会自己找 ffmpeg：
先看设置里 `voice.root` 的 `runtime\ffmpeg.exe`，再看系统 PATH）。想换源文件就用 `--src` 指定。

**不想覆盖内置文件**：在 `config/config.json` 的 `voice` 段里改路径和文案就行：

| 键 | 作用 |
|---|---|
| `signature_file` | 换成别的 wav 的绝对路径；留空 = 用 `assets/voice/taihen_ni_kibun_ga_ii.wav` |
| `signature_text` | 气泡里的中文；留空 = 「心情大好～」 |

**想换表情**：改 `app/voice/signature.py` 里 `DEFAULT_EMOTION`（默认「得意」）。
动作不用管——「得意」在 `assets/expressions.json` 的 `emotion_pose` 里已经映射到抱臂（动作 2），
几秒后会自动恢复默认，时长就是 §9.1 里那个「表情/动作保持多久后恢复」。

**它和测试按钮的区别**：下面的「让她现在说一句」走的是真对话链路（要 Key、会写记录、会算一轮）；
「用日语说一句」走翻译 + 合成（要语音服务）。这个按钮只读本地文件，谁都没启动也能响。

## 9.4 想打电话给她（实时语音通话）

右键她 → 「语音通话（对着麦克风说话）」，或在 设置 → 语音 → 「实时语音通话」里打勾。
开起来之后是**轮流说**：你说完一句 → 她识别、思考、念出来 → 念完自动继续听。

**为什么是轮流说**：要支持"打断"就得一边播一边录，还得做回声消除，否则她把自己的声音当成你在说话。
桌宠场景下轮流说更稳，也不会误识别。

**第一次开会有延迟**：本地识别模型要先下载（约 145 MB，走 `hf-mirror.com`），
提示「正在准备识别模型（首次约 1–2 分钟，之后秒开）」就是在下模型；下完存在 `data/models/`。

**它不花钱、也不上传**：识别在本机 CPU 上跑（`faster-whisper`），录音不上传任何服务器。
只有在设置里把「识别后端」切成 `cloud` 时才走硅基流动接口。

| 设置项 | 对应配置键 | 调它有什么用 |
|---|---|---|
| 对着麦克风说话（开关） | `voice.call_enabled` | 关掉 = 不自动开；开着 = 每次启动自动进入通话 |
| 麦克风 | `voice.call_device` | 留空=系统默认；填设备编号（`sounddevice` 的序号）可指定 |
| 静音阈值 | `voice.call_silence_rms` | 环境吵就调高（0.02），总断句就调低（0.004） |
| 说完多久算一句结束 | `voice.call_silence_ms` | 默认 900 毫秒；说话慢的人可以调到 1200 |
| 最短一句 | `voice.call_min_utterance_ms` | 低于这个长度当咳嗽，不发出去（默认 400） |
| 单句最长 | `voice.call_max_utterance_s` | 一口气说太久会被强行切断（默认 30 秒） |
| 等她念完的上限 | `voice.speech_wait_timeout` | 语音关着时靠这个计时器回到"在听"（默认 20 秒） |
| 识别后端 | `voice.asr_backend` | `local`（免费离线）/ `cloud`（硅基流动） |
| 本地模型档位 | `voice.asr_local_model` | `tiny` 最快但笨、`base` 默认、`small` 更准更慢 |
| 云端 Key | `voice.asr_key` | 留空时借用记忆那栏的硅基流动 Key |

**识别不准怎么办**：先把档位换成 `small`；再看"静音阈值"是不是太低（把她没说话的气音也收进去了）；
中文和日语都能识别，但她念中文名（朝日/游星）容易听岔，这种时候直接打字更快。

**麦克风是自动挑的**：程序会按"上次成功的设备 → 真麦克风 → WDM-KS → WASAPI → DirectSound → MME"的顺序试，
**主动跳过"立体声混音 / Stereo Mix / 扬声器"这类回环设备**（否则她会听见自己念的话，自问自答）。
挑中的设备记在 `voice.call_device_last`（不是给人看的设置项，删掉也没事）。
如果你有多个麦克风想固定用某一个：设置 → 语音 →「麦克风」下拉里选，等价于写 `voice.call_device`。
下拉里**同一支麦克风只会出现一条**（不同接口的同名设备已合并，优先显示 WDM-KS 那条），
带「（打不开）」标注的是当时试开失败的，仍可手动选（换采样率后有时能开）。

**"系统麦克风正常，她却听不见"的坑（本机真发生过）**：
Windows 有**两处**麦克风权限 —— 应用商店的（`ConsentStore\microphone`）和**桌面程序的**
（`ConsentStore\microphone\NonPackaged`）。后者是 `Deny` 时，pythonw / ffmpeg 一律录不到声音，
而 Windows 自带的麦克风测试（商店应用）却完全正常，非常容易误判。
`app/voice/mics.py` 的 `desktop_access()` 读的就是 `NonPackaged` 那个 `Value`；为 `deny` 时：
- 设置 → 语音 顶部会显示一条红字（`QLabel#voiceWarn`）；
- 点「打开 Windows 麦克风设置」直接跳到那一页（`ms-settings:privacy-microphone`）；
- 开了通话却 6 秒没收到任何声音，会主动提示这一条（`recorder.silent`，`SILENT_WARN_MS`）。
程序**不会**替你改注册表 —— 这条系统权限必须你自己点头。

**通话日志**：`logs/voice_call.log`（512 KB 滚动），记着开了哪支设备、采样率、识别到的原话、失败原因。
排查"她没反应"时先看这个文件，比看界面快。

**想改流程**：状态机在 `app/voice/call.py`（开头注释画了状态流转），
录音断句在 `app/voice/recorder.py` 的 `_feed()`，识别封装在 `app/voice/asr.py`，
设备清单与隐私判定在 `app/voice/mics.py`。

## 9.5 想改「她知道的时间」

每次她开口，程序都会往提示词里塞一段【现在是什么时候】：

```
现在：2026年11月7日 周六 13:54（下午，周六，周末）
上一次说话：昨天这个点（约 25 小时前）
```

这段由 `app/timecontext.py` 生成，拼进提示词的位置在 `app/persona.py` 的 `system_prompt()` 里
（【身份】之后、【篇幅】之前）。提示词里明确要求"涉及时间一律以这里为准，不要凭印象猜"，
所以问"今天几号""我们多久没聊了"她能答对。

| 想改什么 | 改哪里 |
|---|---|
| 时段名称（清晨/上午/中午…） | `app/timecontext.py` 的 `part_of_day()` |
| "刚才 / N 分钟前 / 昨天这个点"的分档 | `app/timecontext.py` 的 `gap_text()` |
| 那两行文案本身 | `app/timecontext.py` 的 `time_brief()` |
| 关掉时间感（省几十个字） | 设置里的配置键 `behavior.time_aware = false` |

历史条目里也因此多了一个 `at` 字段（`data/history.json` 里能直接看到）。
老版本留下的、没有 `at` 的记录不会被读崩：程序会按文件修改时间兜底补上。

## 13. 启动脚本（.bat）相关的坑

**这两个文件不要用记事本直接改。** cmd.exe 对批处理有两个硬要求：

1. 行尾必须是 **CRLF**（只有 LF 时，含中文的行会被拆成几条命令）；
2. 编码必须是 **GBK / cp936**（就是中文 Windows 控制台的默认代码页），并且**不能有 `chcp 65001`**。

违反任意一条，双击后就会看到一堆「'xxx' 不是内部或外部命令」，程序根本起不来。

改坏了不要慌，重新生成一遍即可：

```powershell
cd <你的 LunaPet 目录>
.venv\Scripts\python.exe tools\build_launchers.py
```

它会写好两个 bat 并立刻自检（CRLF、无 BOM、无 chcp、能用 GBK 解码）。

**启动失败想看原因：**

| 做法 | 看得到什么 |
|---|---|
| 双击「启动露娜.bat」失败 | 弹中文提示窗 + `logs\启动错误.txt`（完整 traceback 与环境快照） |
| 双击「启动露娜_调试.bat」 | 黑窗口里直接看输出，退出后停在「按任意键关闭」 |
| `.venv\Scripts\python.exe launcher.py --check` | 一条命令体检：Python 版本、依赖、立绘目录、配置文件 |

`launcher.py` 里 `--simulate-error` 是给排查用的演练开关：故意抛一个错，
用来确认「弹窗 + 写日志」这条链路本身有没有坏。
